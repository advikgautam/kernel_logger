# Kernel State Logger

An introductory Linux Kernel Module (LKM) demonstrating how to safely execute code in Ring 0, read internal kernel state, and enumerate live kernel data structures.

## Overview

This project was built to explore how kernel modules are developed, compiled, and managed within a Linux environment. Unlike user-space applications (Ring 3) that rely on system calls, this module runs directly in kernel space (Ring 0).

The module accesses the kernel's internal timer variables to calculate the system's total uptime upon loading, tracks the exact amount of time the module was active before being unloaded, and — as of this update — walks the kernel's live process list to log every currently running process by PID and name.

### Core Concepts Demonstrated

- **Kernel Lifecycle Macros:** Using `__init` and `__exit` to manage module loading and unloading.
- **Kernel Logging:** Using `printk` to write directly to the kernel ring buffer (viewable via `dmesg`), bypassing standard output (`stdout`).
- **Internal Kernel State:** Direct memory access to `jiffies` (the number of timer interrupts since boot) and `HZ` (the timer frequency) to calculate time dynamically.
- **Kernel Data Structure Traversal (New):** Using `for_each_process()` to walk the kernel's live process list, reading each process's `task_struct` to log its PID and name — the same underlying mechanism used by process-monitoring tools, and abused by rootkits to hide processes.

## Prerequisites

This project was developed on **CachyOS (Arch Linux)**. To compile this module, you need the kernel headers matching your current running kernel, along with the LLVM toolchain (as CachyOS kernels are compiled with Clang).

```bash
sudo pacman -S base-devel linux-cachyos-headers clang llvm lld
```

*(Note: If running standard Arch Linux, replace `linux-cachyos-headers` with `linux-headers`)*

## Source Code

### `logger.c`

This is the main kernel module code. It reads the system's timer tick count to calculate uptime and duration, and enumerates active processes on load.

```c
#include <linux/init.h>
#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/jiffies.h>
#include <linux/sched.h>
#include <linux/sched/signal.h>

static unsigned long start_jiffies;

static void list_processes(void) {
    struct task_struct *task;

    printk(KERN_INFO "LOGGER: --- Active Process List ---\n");

    for_each_process(task) {
        printk(KERN_INFO "LOGGER: PID: %d | Name: %s\n", task->pid, task->comm);
    }

    printk(KERN_INFO "LOGGER: --- End of Process List ---\n");
}

static int __init logger_init(void) {
    unsigned long uptime_seconds = jiffies / HZ;
    start_jiffies = jiffies;

    printk(KERN_INFO "LOGGER: Module loaded.\n");
    printk(KERN_INFO "LOGGER: System uptime is %lu seconds.\n", uptime_seconds);

    list_processes();

    return 0;
}

static void __exit logger_exit(void) {
    unsigned long active_jiffies = jiffies - start_jiffies;
    unsigned long active_seconds = active_jiffies / HZ;

    printk(KERN_INFO "LOGGER: Module unloaded.\n");
    printk(KERN_INFO "LOGGER: Module was active for %lu seconds.\n", active_seconds);
}

module_init(logger_init);
module_exit(logger_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Advik Gautam");
MODULE_DESCRIPTION("Kernel State Logger with Process Enumeration");
```

### `Makefile`

The Kbuild instructions required to compile the module. Note the explicit use of `LLVM=1` to ensure compatibility with CachyOS.

```makefile
obj-m += logger.o

all:
	make LLVM=1 -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make LLVM=1 -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean
```

## Build and Execution Guide

### 1. Compile the Module

We use the kernel build system (Kbuild) via our `Makefile`. Because of compiler differences in CachyOS, we explicitly pass the `LLVM=1` flag to compile with Clang.

```bash
make
```

If successful, this will generate a `logger.ko` (Kernel Object) file.

### 2. Load the Module into the Kernel

Loading a module requires root privileges. This action instantly triggers the `logger_init` function, which now also walks and logs the full process list.

```bash
sudo insmod logger.ko
```

### 3. Verify Initialization (Uptime + Process List)

Check the kernel ring buffer to see the output generated by the module.

```bash
dmesg | tail -n 20
```

**Expected Output:**

```
[  +0.000000] LOGGER: Module loaded.
[  +0.000000] LOGGER: System uptime is 3600 seconds.
[  +0.000000] LOGGER: --- Active Process List ---
[  +0.000000] LOGGER: PID: 1 | Name: systemd
[  +0.000000] LOGGER: PID: 2 | Name: kthreadd
[  +0.000000] LOGGER: PID: 512 | Name: firefox
[  +0.000000] LOGGER: --- End of Process List ---
```

### 4. Unload the Module

Gracefully remove the module from the kernel. This triggers the `logger_exit` function, which calculates how long the module was active.

```bash
sudo rmmod logger
```

### 5. Verify Cleanup (Module Active Time)

Check the kernel logs one last time to see the exit message.

```bash
dmesg | tail -n 5
```

**Expected Output:**

```
[  +0.000000] LOGGER: Module unloaded.
[  +0.000000] LOGGER: Module was active for 45 seconds.
```

## Disclaimer

This code interacts directly with the Linux kernel. While this module is designed to be safe — it only *reads* kernel data structures, it never modifies them — a fatal error in kernel space will cause a Kernel Panic and crash the system. Never test experimental modules on production machines without saving your work!
